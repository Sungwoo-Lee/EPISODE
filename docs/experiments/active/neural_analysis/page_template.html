Neural Recording Pipeline

So far every result in this project has come from the agents' behaviour. This plan adds the other half of a neuroscience experiment: recording the activity of every unit in the agents' networks while they act, and analysing it with the standard methods of systems neuroscience. The first analysis is the encoding model (a general linear model, GLM) that asks which experimental variables each unit represents.

PURPOSE

The behaviour studies found that, in some training worlds, an injured agent hides more when a harmless rabbit is near than an unhurt agent does — the hypervigilance pattern. Behaviour alone cannot say how the network produces it: whether injury is represented at all beyond the injury signal the agent receives as input, where in the network it meets the information about the animal, and whether the neuromodulator changes that. Those are questions about the network's activity.

The data are organised as in a Neuropixels or fMRI study: each unit (one artificial neuron) is a channel with a full time series over each episode, and time-aligned records of the experimental variables sit beside it. Any standard method — encoding models first, dynamical-systems analyses later — then reads the same files. Nothing has been recorded yet: the figures in section 06 are drawn from simulated numbers to fix how results will be shown. They will be redrawn from a pilot run's real recordings.

Decided with the user (2026-10-15). Record every unit, not selected layers; record two conditions — the training condition (the agent's own training world) and the experiment condition (the frozen behaviour test scenes), both played by the trained agent — and test whether the encoding found in one holds in the other; one file per unit of collection work, so files stay few but collection runs in parallel; use the terms of the neuroscience literature; the unit map of Figure 2 is the main figure, the per-regressor maps an appendix.

01 What is recorded

Every value the network computes at each step, for both agents of the level-05 lookalike study: the ordinary agent and the modulated agent (the same network plus a 16-unit recurrent modulator that rescales four of its layers through FiLM, feature-wise linear modulation: γ · x + β, a per-unit gain γ and bias β). Feed-forward layers are recorded both before the activation function (pre-activation, the analogue of input current) and after it (post-activation, the analogue of a firing rate), and, in the modulated agent, also right after FiLM. The recurrent layer is a gated recurrent unit (GRU), whose hidden state is both its memory and its output.

02 Which episodes

The networks learned their activity patterns in their training worlds, while the behaviour test scenes are deliberately unlike training. An encoding model fitted only in the test scenes would describe the network in an unfamiliar, controlled situation, which need not match how it represents the same variables in normal behaviour (a distribution shift). The networks are therefore recorded in two conditions, as a free-behaviour session and a controlled task are in neurophysiology:

Terms (user, 2026-10-16). Condition always means one of the two data sets below, and every analysis uses the trained agent. The terms keep apart the time when the agent learns and the data the analysis is run on:

training phase
The period in which the network's parameters are updated by the learning algorithm (proximal policy optimisation, PPO), here 10 million environment steps. No analysis data are taken from it.
checkpoint
A snapshot of the parameters saved during the training phase, named by its step count.
trained agent
The network with its parameters fixed at the final checkpoint, unless a page states another checkpoint. It no longer learns: data collection only runs the policy forward (inference), with greedy action choice and no parameter updates.
in-training evaluation
The three episodes that the training program plays and records at each checkpoint to monitor progress. They are monitoring output only and are not analysed.
training condition
The trained agent playing fresh episodes in its own training world: the in-distribution data set, the analogue of a free-behaviour session in neurophysiology.
experiment condition
The trained agent playing the frozen behaviour test scenes, whose layout differs from training on purpose: the out-of-distribution data set, the analogue of trials of a controlled task.
distribution shift
A difference between the situations a network was trained on and those it is tested in; here, the difference between the training condition and the experiment condition.

Training condition (free behaviour). Episodes played by the trained agent in the run's own training world, from fixed seeds, until death or the episode limit, so their lengths vary. This is the distribution the network was trained on and the more varied data set, used as the main fitting set. 500 episodes per run and checkpoint are proposed; their size is measured on the pilot, because episode lengths are not known in advance.

Experiment condition (controlled task). The trained agent plays the frozen test scenes already used for the behaviour results: the agent in the middle of the map, one bush three cells away, no campfire; a starting injury from 0 to 90; no animal, a wandering rabbit, a chasing rabbit or a predator; healing off (test only) or on. Each scene has 30 episodes of 100 steps, from fixed seeds. Recording the same episodes as the behaviour results makes the two directly comparable: in neuroscience terms these are trials of a controlled task, where injury and the animal are set exactly.

The encoding model is fitted in each condition and scored in the other (cross-condition generalisation, section 05). Tuning that holds in both is a robust property of the network; tuning that appears in only one shows that the representation depends on the context.

The agents have no sensory noise in either condition, so replaying the same checkpoint, scene and seed gives exactly the same activity. A recording can therefore be deleted and regenerated identically; it is a cache, not an irreplaceable dataset.

03 Data structure

One HDF5 file per collection job: for the experiment condition, one run, one checkpoint and one starting-injury level (all its animal and healing settings); for the training condition, one run, one checkpoint and a block of episodes sized to a similar file size. The trials table records each episode's condition, so both conditions share one layout. That is the unit of parallel work — one worker writes one file — so the number of files equals the number of jobs that can run at once (a few hundred), never one file per episode. HDF5 holds many arrays in a single file and reads a slice without loading the rest. The layout follows the conventions of Neurodata Without Borders (NWB), the standard format for neurophysiology data:

← wider than the screen — scroll it sideways

<run>__ckpt<step>__inj<level>.h5
├── activity/                 one array per recorded quantity, float16 [episode × time × unit]
│   ├── rnn.state             GRU hidden state                    [E × 100 × 128]
│   ├── enc.uni.out           encoder stage 1, post-activation    [E × 100 × 9·128]
│   ├── actor.raw, actor.out  …every key of Table 1
│   └── film.z_actor, …       FiLM gain γ and bias β per site     (modulated agent)
├── units                     table: unit id, layer, site, sensor group, pre/post activation
├── trials                    table: episode id, scene, starting injury, animal, healing, seed, length
├── regressors                table, one row per (episode, step): the design-matrix variables
│                             injury, observed injury, satiation, body temperature, animal class and
│                             distance per animal, animal in view, on bush, action, alive, time
├── events                    table: episode, step, event (animal enters view, predator hit,
│                             bush entry, bush exit, injury onset, eating), animal class
└── meta                      run, checkpoint, git commit, scene files and hashes, collector version,
                              replay-parity check against the behaviour sweep

Episodes that end early (the agent dies) keep a full 100-step array, padded with NaN after the last step; trials.length says where each one ends. A small index file per study lists every recording file with its job and validation status.

04 Collection pipeline

STEP 0
Complete the capture
Extend the model's capture function to also return the hidden layers inside the two encoder networks, so every unit is recorded. A code change, reviewed by code-reviewer; an existing test already checks that every captured layer recomputes from its upstream neighbour.
STEP 1
Run manifest
An explicit list of runs and checkpoints (YAML), not a name pattern: the existing analysis tools find runs by patterns that skip the lookalike runs, and resumed runs have several folders.
STEP 2
Replay and capture
Experiment condition: each job replays its scenes with the existing exact-replay path (scripts/analysis/obs_manipulation/run.py, live mode, no manipulation) with capture on. Training condition: each job plays fixed-seed episodes in the run's own training world with the existing replay tool (scripts/analysis/nmn/replay.py) and capture on. Both use the trained agent, and both record activity plus the environment state that the regressors are computed from.
STEP 3
Write one file, in parallel
One worker per job across the lab nodes; a job that finds a valid file skips it, so a stopped collection resumes.
STEP 4
Validate
The replay must reproduce the behaviour sweep's actions and positions step for step (parity); shapes and NaN padding must match trials.length; each layer must recompute from its upstream neighbour. A file that fails is deleted and its job rerun.
STEP 5
Pilot, then scale
Record the pilot set first, measure file size, speed and compression, and redraw this page's figures from it. Only then record the final checkpoint of every run.

05 First analysis: the encoding model

An encoding model predicts each unit's activity from the experimental variables, as is done for recorded neurons (Pillow et al. 2008; Park et al. 2014; Musall et al. 2019). One model is fitted per unit:

yu(t) = Σk βu,k · xk(t) + εu(t)

where yu(t) is unit u's activity at step t, each xk(t) is a regressor and βu,k its coefficient. The terms used below:

regressor
One experimental variable used as a predictor: injury, observed injury, satiation, rabbit present, predator present, nearest-animal distance, on bush, action, time in episode.
design matrix
All regressors stacked as columns, one row per time step.
dummy variable
A 0/1 column coding a category, e.g. "rabbit present".
interaction term
The product of two regressors (injury × rabbit present). Its coefficient measures how much one variable changes the effect of the other.
event regressor
Time-shifted copies of an event indicator (e.g. the rabbit entering the field of view), one per lag; their coefficients form the unit's response kernel. Negative lags capture activity before the event.
FIR basis
Finite impulse response: one free coefficient per lag, so the kernel's shape is not constrained (Figure 1).
parametric modulation
An event block multiplied by a continuous variable (here injury), so the event's kernel may scale with that variable.
boxcar regressor
A 0/1 column that is 1 for as long as a state lasts, e.g. on the bush.
ridge regression
Linear regression with an L2 penalty on the coefficients, which keeps estimates stable when regressors are correlated (Hoerl & Kennard 1970).
cross-validation
Fitting on some episodes and scoring on held-out ones. Whole episodes are held out, because steps within an episode are correlated.
cvR²
Cross-validated R²: the share of a unit's variance predicted on held-out episodes.
unique explained variance (ΔR²)
The drop in cvR² when one regressor is removed and the model refitted: the variance only that regressor explains (variance partitioning; Musall et al. 2019).
selectivity
A unit is selective (tuned) for a variable if that variable explains its activity; mixed selectivity means one unit encodes several variables (Rigotti et al. 2013).
permutation null
The distribution of ΔR² when the link between regressor and activity is broken, here by circularly shifting the regressor in time within each episode, which keeps its own time structure.
false discovery rate
The expected share of false positives among units called significant; controlled with the Benjamini–Hochberg procedure across the many units tested.

Cross-condition generalisation. A model fitted on the training condition is scored, without refitting, on the experiment condition, and the reverse. The drop in cvR² from the fitting condition to the other one measures how much of a unit's encoding is specific to that condition. The regressors are defined identically in both conditions so the same coefficients apply.

Statistics across agents use the seed (an independently trained network) as the unit of replication, never the unit: units within one network are not independent.

06 Figures, with simulated numbers

Every figure in this section is drawn from made-up numbers (each is stamped “MOCK-UP”). They show how results will be presented, not any result. The unit maps draw 128 units per layer and 16 FiLM outputs per site to stay readable; real maps draw every unit (Table 1), the encoder's first stage as one block per sensor group. Each figure carries a short “Analysis” note instead of the full “How it is computed” block of 150–250 words that results pages carry (generation guide §11c): there are no results to compute yet, and the full blocks come with the first real recordings.

Figure 1 — the design matrix and its event regressors

Analysis. The design matrix of one episode. Time runs left to right, regressors down the rows — transposed from the usual neuroimaging (SPM) convention, so the episode's event strip and the matrix share one time axis. Continuous regressors (injury, observed injury, satiation, nearest-animal distance) and state regressors (rabbit present, predator present, on bush, a 0/1 “boxcar” that is 1 for as long as the state lasts) are single columns; the injury × rabbit interaction is their product. Each event is a block of time-shifted indicator columns, one per lag — a finite-impulse-response (FIR) basis — which appears as a diagonal band; the fitted coefficients of one block are that event's kernel (Figure 4). The events planned are: bush entry, with lags from 10 steps before (the approach, when the agent is moving to hide) to 10 after; bush exit, ending a hiding and resting period; injury onset (a predator attack or a hazard hit, 0 to +20 steps); animal enters the field of view, separately for rabbit and predator (−5 to +20); and eating (each bite, 0 to +5). Time spent in the bush enters both as the state column and through the entry and exit kernels. Negative lags let a unit respond before an event the agent itself causes, such as entering the bush, which is how preparatory activity is detected. The FIR basis assumes no response shape, which suits units whose responses are not known in advance (unlike the BOLD signal, whose slow haemodynamic response justifies a canonical shape in fMRI); its cost is many coefficients and noisier kernels. The alternative is a small set of smooth basis functions (raised cosines; Pillow et al. 2008; Park et al. 2014). Pilot decision: both are fitted on the pilot recordings and the basis with the higher held-out cvR² is kept, checking that the kernel shapes agree. Event colours follow the regressor palette: each event takes the colour of the state it belongs to (bush entry and exit that of on bush, eating that of satiation).

Variable onsets and durations. Events happen at different times, and states last different lengths of time, in every episode and in both conditions. The design matrix is built per episode from that episode's own event times, and the coefficients are shared across episodes, so each kernel is the response time-locked to its event wherever the event falls (as in event-related fMRI with jittered onsets); timing that varies also decorrelates the lagged columns of different events, which helps separate overlapping responses (deconvolution). A period of variable length is modelled by three parts: an entry kernel (the transient at its start, including the approach before it), a boxcar state column for the sustained response however long it lasts, and an exit kernel. Lags are never carried across episodes. The model assumes an event's response has the same shape each time (linear, time-invariant); where the response may depend on the agent's state, a second copy of the event block multiplied by that state is added — parametric modulation. The planned case is rabbit enters view × injury, whose kernel is how injury scales the event-locked response to the rabbit.

Figure 3 — proportion of tuned units per layer

Analysis. For each layer and regressor, the proportion of units whose ΔR² exceeds the permutation null at a false discovery rate of 5 %. This is the counterpart of the “fraction of selective neurons per brain region” in large-scale recordings (Steinmetz et al. 2019). Comparing observed injury (the input) with injury (the body state) per layer shows where the network carries injury beyond its input.

Figure 4 — event kernels

Analysis. The event regressors' coefficients give each unit's temporal response kernel around an event (here the rabbit entering the field of view; Pillow et al. 2008; Park et al. 2014). Units are sorted by peak latency, the lag at which their kernel peaks; the top trace is the mean absolute kernel over units. It is the GLM counterpart of the peri-event time histogram (PETH), with overlapping events and the other regressors controlled for.

{{FIG:np_kernels}}

Figure 5 — tuning curves

Analysis. A tuning curve is mean activity as a function of a variable, here the starting injury, separately with no animal and with the rabbit present. A constant gap between the curves is an additive effect; a gap that grows with injury is a multiplicative interaction, or gain modulation (Salinas & Thier 2000): injury scales the response to the rabbit, the neural counterpart of the hypervigilance pattern. The right panel averages the units tuned to the interaction.

{{FIG:np_tuning}}

Figure 6 — nested model comparison

Analysis. Regressor groups are added one at a time — time only, then the sensory inputs, injury, animal identity, injury × animal — and each step's gain in cvR², averaged over a layer's units, is how much that group adds beyond the previous ones. Entering the sensory inputs before injury separates the representation of an internal variable from a response driven by the injury signal in the input.

07 Open points

  • Pilot runs and checkpoints. Proposed: two worlds with the clearest behavioural effect, both agents, about ten checkpoints across training.
  • Encoder sensor groups. A known bug (registry: alphabetical group order inside jit) means a stage-1 group's name does not match the sensor it reads; group labels must come from the true order before any per-sensor statement.
  • Dynamical-systems analyses (population trajectories, fixed points of the recurrent layer, how injury moves its operating point) read the same files and get their own section once the encoding model is running.
  • Training-condition episode count. 500 episodes per run is a starting proposal; the pilot measures episode length and file size, and the count is fixed so the encoding model's held-out score is stable.
