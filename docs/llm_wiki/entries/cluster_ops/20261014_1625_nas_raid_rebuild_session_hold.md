# NAS disk rebuild: pause heavy work, keep talking

## Key conclusion
When the NAS is rebuilding a failed disk, the safe move is to pause NAS-heavy work in every session, not to stop all sessions. Conversation with Claude is light, because transcripts are written to the local disk, not the NAS. The rebuild matters because the gitignored data (results, wandb, logs, claude_data) exists only on the NAS. Scripts and docs are already on GitHub.

## Evidence, measurements, facts
- Alert from the lab's computer manager on 2026-10-11, about 18:37 KST: one NAS hard disk failed, and the hot-spare rebuild ran in fast-resync mode with ~20 h left (expected to end about 10-12 14:40). The request was to keep NAS reads and writes to a minimum; using the NAS was allowed, but stability came first.
- The NAS is the CIFS share //192.168.0.250/cocoanlab01, mounted at /media/nas01. `~/.claude` (session transcripts) is on the container's local overlay disk.
- Heavy work found and paused:
  - the GPU monitor web app's NAS scanner child process, paused with SIGSTOP and resumed later with `kill -CONT <pid>`; the web app itself kept running;
  - Training's analysis sub-agent, stopped with its notes saved to `tmp/`;
  - Behavior's artifact format-review agent and a wait loop.
  Paper was idle.
- Things counted as heavy: training launches, artifact builds and rendering, reads of large result stores, commits and pushes (which re-stat the repo on the NAS), and recursive searches.
- Exception: the user explicitly allowed one full read of 27 one-million-episode trajectory stores in the middle of the hold. The reads ran on lab nodes, which still load the NAS. They finished in one pass, and that session went back to holding.

## Decisions and actions
- The Admin session messaged each session, using the prefix "[From the Admin session, on the user's instruction]", to suspend heavy work and report back. All three confirmed.
- Light work went on: discussion, and editing one small skill file. Its commit was deferred until the rebuild ended.
- A session that is told by the user to do heavy work anyway goes ahead and announces it. The Admin session does not overrule a direct user choice.

## Open questions and follow-ups
- After the rebuild, resume the scanner, commit the deferred `/takeaway` skill change, and release the sessions. The user gives the go-ahead.
