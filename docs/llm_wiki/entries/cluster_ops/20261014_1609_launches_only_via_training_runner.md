# Training launches go only through training-runner; scripts detect and report

## Key conclusion
A launcher script that bypasses the training-runner agent silently drops the runner's checks and records. The rule
now (user, 2026-10-14) is: the top-level session orchestrates (free cards, placement, order, stopping a run at a
checkpoint, often from a `/loop` tick), `training-runner` launches and resumes (one spawn per run), and scripts or
watchers may only detect and report. Every session doing training work reads `docs/environment/TRAINING_OPERATIONS.md` first.

## Evidence, measurements, facts
- 2026-10-13 23:50 a queue watcher (`tmp/20261013_hf_seeds_watch/watch.py`) took over launching 14 queued
  half-factorial seed runs, one per card as cards freed. By 2026-10-14 15:30 it had launched 13.
- It wrote diary rows only. Missing for all 13: run-registry rebuild (runner §4e), design-doc run table (card,
  time, WandB id — all still "queued"), `train_command-agent.sh` entries.
- The user had started a 15-min `/loop` "check GPUs and launch the planned training"; I treated the loop as a
  monitor of the existing script instead of spawning training-runner when a card freed, which is what the user meant.
- The training-runner cannot find free cards itself (no monitoring source), so it cannot wait for cards; that is why
  the orchestrator role exists.

## Decisions and actions
- Queue watcher stopped 2026-10-14 15:56; remaining launches and the node-112 move go through `/loop` + training-runner.
- Created `docs/environment/TRAINING_OPERATIONS.md` (who does what, free-card checks, records incl. run registry,
  resume/move rules, incident log, live lab constraints, tooling-change log); CLAUDE.md carries a one-line pointer;
  the runner profile requires reading it before every launch; AGENT_PLAYBOOK has a short pointer subsection.
- Fixed CLAUDE.md agent table: the runner's file is `train_command-agent.sh`, not the user's `train_command-new.sh`.

## Open questions and follow-ups
- Queued launches now happen only while a session is alive; tell the user when runs will wait overnight.
