# Plan review: episode-video renderer redesign

**Reviewed by**: plan-reviewer · **Date**: 2026-09-14 · **Object**: [`docs/develop/active/refactors/RENDERER_LAYOUT_REDESIGN.md`](../develop/active/refactors/RENDERER_LAYOUT_REDESIGN.md) (drafted today by `senior-developer`; not yet approved; nothing committed)

Severity legend: 🔴 Critical = fix before going further · 🟡 Moderate = likely costs a re-run · 🟢 Low = cosmetic · ❓ Open = an assumption nobody has verified yet.

## Verdict

**NOT READY** — two Critical findings, both cheap to fix in the doc before any code is written.

The plan proposes a second renderer for the evaluation videos (the dashboards showing the agent's body readings, a map, and its senses) that computes a box for every panel once per episode, draws strictly inside each box, and proves the absence of overlaps by inspecting rendered pixels rather than trusting the layout code. The architecture, the verification design and the compatibility handling are well thought out and mostly failure-detectable. The plan is blocked by two things it *says*, not by how it plans to build:

1. **It names the interoceptive-nociception signal "PAIN".** The row label in the layout blueprint reads `PAIN`, and the plain-language sections describe the signals as "pain", "touch-pain" and "internal pain". The project's standing rule is that the signal is nociception; "pain" is the thing the project is trying to explain, so it must never be the name of an input. A label in a renderer is baked into every video and every figure cut from one.
2. **It leaves undecided whether Nutrition and Injury rows appear when the agent cannot observe them, and inherits V1's habit of printing a state value under the caption "OBS".** In the campfire temperature world, the agent's observation contains no Nutrition and no Injury; V1 still draws both rows and labels the true state value as "OBS" (`src/environment/renderer.py:829`, `:837`). The registry table copies this ("in breakdown **or** always"). A viewer of such a video would conclude the agent perceives its injury when it does not — a wrong claim about sensory access, which is the project's central variable.

Everything else is Moderate or lower. The strongest Moderate items: the pixel audit lets the painter under test declare which of its own ink is exempt from collision checks; the "silent panel drop" detector has no positive control; the V1 byte-identical baseline omits the thermal path that the new code will share helpers with; and the plan rejects the browser-based option partly on a premise ("Chrome may be absent on lab nodes") that a direct check today shows is false on the three nodes sampled.

**What flips the verdict:** (1) replace "pain" wording throughout the doc and use a nociception label in the blueprint (e.g. `INOC` / `NOCI`); (2) rewrite the vitals presence rule so rows are derived from `get_observation_breakdown` and a hidden state value, if shown at all, is never captioned as observed.
