## Verdict (plain language)

The water and thirst change adds a fourth bodily need to the grid world: a small pond that the agent can stand on to drink, and a hydration level that drains every step and kills at both ends (too dry, too full). This audit asks one question: **are the configuration files that switch this on safe to train with, and do the files that leave it off really leave the world untouched?**

Answer: **yes on both counts, with two things to fix that do not block a launch.** Every rung of the training ladder loads through the trainer's own loader path, produces the observation widths the plan promised (44, 44, 52, 52, 52, 58, 59, 59 numbers per step), and every sensor in every rung has a matching noise entry, so the runtime crash that a missing entry causes cannot happen here. Levels 06 and 07 differ from their parents in exactly the fields they are supposed to and nothing else. Every new setting is read with the strict "no fallback" accessor and only when water is on. The pond-capacity check refuses worlds that would otherwise park an entity at the corner cell. The noise rung (07) states its hydration noise as zero explicitly rather than inheriting the base's 0.1, which is the recurrence the registry warns about.

The two findings worth a fix: (1) the master switch `water.enabled` accepts any "truthy" value, so a quoted string like `"false"` would turn water **on** — the plan said the key is validated as a boolean, and the sibling key `random_start_hydration` is, but the gate itself is not (the older `thermal.enabled` gate has the same gap); (2) the canonical environment reference still says the noise system has 12 modalities and "one spare slot remains", which stopped being true the moment the hydration modality took the 13th and last slot — the schema document was corrected in the same change, the summary was not. Neither costs a re-run today; both are cheap to close before this branch is merged.

**Severity legend — reproduce it verbatim in every report so the labels never need looking up:** 🔴 Critical = fix before going further · 🟡 Moderate = likely costs a re-run · 🟢 Low = cosmetic · ❓ Open = an assumption nobody has verified yet.
