# Plan review — thermal probe battery for bush hiding in the level 05/06 agents

**Reviewed by:** plan-reviewer
**Verdict:** **NOT READY** — one Critical finding, resolvable without touching any config.

Severity legend: 🔴 Critical = fix before going further · 🟡 Moderate = likely costs a re-run · 🟢 Low = cosmetic · ❓ Open = an assumption nobody has verified yet.

## Verdict, in plain language

The design wants to know whether agents that carry a neuromodulator hide in bushes *differently* from agents that do not — specifically, whether the plain agent simply parks itself in the bush for the whole episode while the neuromodulated agent goes in only when a predator is near. Its sharpest test is a world where the bush is deadly cold and the only warm place is a campfire on the far side of the arena: a parked agent should freeze there, a responsive one should leave. The design then writes down, in advance, that it will count the test as passed if the plain agent loses at least 30 percentage points more of its survival time than the neuromodulated one, and as a null if the gap is under 10 points.

**That rule cannot be met by the mechanism it is testing.** I ran the real environment: an agent that walks straight into the deadly bush and sits there dies at step 93 of a 100-step episode. An agent that never moves at all also dies at step 93. An agent that walks to the fire survives all 100. The largest survival gap the freezing mechanism can ever produce is therefore 7 points — inside the design's own "null" band. Run as written, the battery would report "no difference" whatever the agents actually do, and that null would be believed because it was pre-registered. The design measured the 86–99-step freeze latency itself (its §4) and then did not carry it into its §5 thresholds.

The fix is cheap and needs no config change: replace the survival-step rule with a rule about *how* the episode ended (every recording already stores whether the agent froze, was killed, or reached the cap) and about *where* the agent was, and promote the empty-world scene — the one that produced the level-04 finding in the first place — to the primary parked-vs-conditional test. Details and the exit condition are in §1 below.

Everything else is Moderate or lower: a bush that is permeable to the predator here but not in training (already flagged as a confound in another review today), an analysis plan that reads the aggregate hiding number the prior work showed cannot separate parked from responsive, a driver whose failure path is silent, and a single training seed per arm.

## 3. Cost of being wrong

If the battery launches as written, ~3 node-hours are spent and the pre-registered `fire_away` test returns a null that is *structurally guaranteed* — and because it was pre-registered it would be believed, shelving the parked-vs-conditional question for the thermal agents on evidence that never could have supported it. No data is lost and nothing is irreversible; the cost is a wrong conclusion in a study note, and a rerun is not even needed if the recordings are re-read under corrected rules.

## 4. What would flip the verdict to SOUND WITH CONCERNS

1. §5 replaces the survival-step `H₁a` rule with a termination-reason rule in the non-predator `fire_away` scenes plus the empty-world contrast in the comfortable arms (finding 1).
2. §2.3 names the permeable-bush confound and §3.2/§8 add the post-sweep gate for `fail_*` and row counts (findings 2, 4).
3. A `--max-checkpoints 1` smoke pass into a separate `output_dir` is written into the manifest as job 0 (finding 5).

Findings 3, 6, 7, 8 are recommended but do not gate launch.
