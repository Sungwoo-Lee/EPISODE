# Plan review: hypervigilance analysis tooling

**Object reviewed:** [[HYPERVIGILANCE_ANALYSIS_TOOLING]] (`docs/develop/active/behavior/HYPERVIGILANCE_ANALYSIS_TOOLING.md`, commit `27d63da3`), the tooling plan for the single-channel-smell study [[SINGLE_CHANNEL_SMELL_HYPERVIGILANCE]] — checked against the study doc **as it stands after Revision 2** (commit `7ec62720`), not the earlier text the plan quotes.

## Verdict

**NOT READY** — one Critical, five Moderate (a sixth, R6, was resolved by study Revision 3 `86ce3119` while this review was being written), three Low, four Open assumptions.

In plain terms: the plan's design is right — one shared definition of "how predator-like an animal smells" that works for all three smell worlds and refuses anything else, every new number in a new file so the old files stay byte-identical, and a gate that must reproduce already-published numbers before any new result is looked at. The block is in that gate. Its reference for the "What makes this agent hide?" page is an aggregate file written at 14:39 on 2026-08-25, six hours *before* the same-day commit that added six more columns to that file's schema. The gate tool treats an extra column in the candidate as a failure, so the gate cannot pass for any version of today's code — including the unchanged one — and the plan's "cheap, no-sweep" CSV check will crash on the old code for the same reason. Left as written, the developer reaches a gate that fails for a reason unrelated to the change, and the tempting fix is to loosen the gate, which its README forbids. The fix is cheap in words and a few hours in compute: regenerate the reference with the pre-change code at the base commit, exactly as the plan already proposes for the CSV.

The other findings are about the study's rule having moved on since the plan was drafted (the plan says three revisions are "not yet in the study text"; they landed in Revision 2), a population picker that would silently read a failed run instead of its relaunch, a smoke mode with no implementation path, a scent-times-injury reading whose control reference is not like-for-like, and three designer choices that must be registered before the first treated store is read.

Severity legend: 🔴 Critical = fix before going further · 🟡 Moderate = likely costs a re-run · 🟢 Low = cosmetic · ❓ Open = an assumption nobody has verified yet.

## What was verified (so the reader can skip re-checking it)

- **Three copies of `smell_channels`** at the lines the plan cites (`core/env.py:73-82`, `hiding_drivers.py:81-97`, `figures/_common.py:57-67`); `_common.py`'s copy has no importer in `scripts/analysis/figures/` (grep: six scripts import `_common`, none imports `smell_channels`).
- **Byte-identity design for the two-channel layout is sound**: `statistic` = the same `prop[..., a] − prop[..., b]` expression as `hiding_drivers.py:178-179`; `intensity` = the same `prop[..., a] + prop[..., b]` as `collect_arm_data.py:74-75` and `hiding_drivers.py:184-185` (two-operand IEEE addition is commutative); no existing JSON/npz gains or loses a key; S6 lands in a new file. G2's reference (`results/analysis/basicq2_integrated/ladderstyle/w2_lvl05_control.json`) carries exactly the key set today's `collect_arm_data.py` writes, and its `run`/`stores` equal the `_manifest.json` row, so G2 is a genuine system-produced reference — unlike G3 (R1).
- **The three evidence-scale factors** recompute from the study's Appendix-B values: `0.4/0.18 = 2.222`, `0.2/0.09 = 2.222`, `0.28/0.18 = 1.556`; midpoints 0 / 0.6 / 1.2; the S3 thresholds at 2/3 nat: 0.3 / 0.9 / 1.6286 (study says 1.63). `x1 − x2`, `x1`, `x1 + x2` are the sufficient statistics for the three layouts (class means differ along (1,−1), (1,0), (1,1) with isotropic equal spreads).
- **The archived S3 script** (`supplementary/falsealarm.py`) does what the plan says: slots `P=[0,1]`, `R=[2,3]`, `D=2`, exactly one predator and one rabbit, rabbit-like `rp < 0.0`, predator-like `rp >= 0.3`, predator-near precedence (`rn = near[:,R].any(1) & ~pn`), distances on the **same** row as the bush state, time share per state `C[g,s]/C[g].sum()`. `curves.py` bins `[-1,-0.2,0,0.2,0.4,0.6,1.01]` — bottom sixth `< −0.2`, top `≥ 0.6` — and computes no food/starved/killed columns, as the plan says.
- **Published a01 numbers** in the a01 doc: rabbit +1.6 / predator +1.7 pp per SD (lines 85-86; the CSV's `dpp_per_sd` 1.6117 / 1.7154); extreme rows 14.9 / 22.6 %, 193.3 / 175.6 steps, 29.7 / 35.0 %, 88.9 / 115.4 (lines 137-143); aimed split +8.0 / +6.4 / +23.1 pp, 26.7 → 49.8 %, 13.0 vs 14.3 % (lines 155-169).
- **`a4_hypervigilance.hiding_shift`** lives at `scripts/analysis/studies/modulator_clues/a4_hypervigilance.py:34-36` and is exactly `proximity_effect(…, (3,)) − proximity_effect(…, (0,))`; the module creates a figure at import (`:55`), so the plan's re-statement is the right call. Its `COLS` = the two blind cells + levels ≥ 4 of both waves = 14 cells; the clue page's caption carries −1.9 and +0.3.
- **cmp10m as yardstick**: the five run dirs and stores exist (`results/trajectories_nmngae/20260904-*_rppo_cmp10m_gaenorm_s42…s46`); the saved config has the same two-channel layout (predator `[0,0.7,0.5,0,0]`, rabbit `[0,0.5,0.7,0,0]`, SD 0.3), `random_start_injury: true` on [0, 100] (so P2's quarters are populated), `olfactory_grid_range 0`, `visual_sensor_range 0` with `visual_vector_size 8` (own-cell vision only), and every sensory key `sensory_summary` reads (no KeyError on the sweep). The store's episode and step tables carry every column the four sweeps read. Known Bugs row "five 2026-09-04 reference runs sit at a different level — use them for spread, never as a baseline" is exactly the plan's use.
- **S1 sample**: no-predator, exactly-one-rabbit episodes ≈ 11 % (≈ 110 k per run, ≈ 27 k per start-injury quarter); with LLR SD ≈ 0.94 nat (control) / 0.67 nat (treated) the within-run standard error of the quarter contrast is ≈ 0.3–0.4 pp per nat against a 2 pp-per-nat minimum, so seed noise, not sample size, limits S1 — as intended. ## Assumptions the plan rests on (❓ Open unless marked verified)

- *Verified:* the three cited line ranges; G2's reference provenance; the evidence-scale factors; the S3 conventions; the a01 numbers; cmp10m's world and store columns; `golden.py`'s MISSING semantics.
- ❓ A1: the cmp10m between-seed SDs are a fair proxy for seed noise in worlds where the rabbit percept differs (cmp10m smells without direction and sees only its own cell). They are the same SDs the registered power table already used, and the yardstick only re-states power, so the rule is unaffected — but the verdict should print the hv control arm's own between-seed SD (3 seeds per agent) beside the frozen yardstick, labelled post hoc.
- ❓ A2: the "food per step / starved / killed" extreme-row columns follow the obvious definitions (`n_ate / n_steps`, termination shares); the plan correctly says a mismatch is reported, not tuned.
- ❓ A3: the C01/C02 re-collection into `results/trajectories_hvsmell/` (not yet present) happens with the current collector before `hvsmell` is swept; the ground-truth checks in `readings.py` would catch a wrong store, not a missing one.
- ❓ A4: S6's `np.bincount` accumulators add < 10 % wall-clock to `collect_arm_data` (C11 measures it).

## Cost of being wrong

If R1 stands, the first `golden_check.py` run fails with dozens of MISSING keys for a reason unrelated to the change; the day is lost either to a full re-sweep the plan did not budget, or — worse — to loosening the golden gate, after which the byte-identity guarantee every published number relies on is gone for good. If R3 stands and one of the sixteen runs crashes, a treated seed's verdict is read from a failed run's store without anyone noticing. If R2 stands, the verdict map is scored on a rule the study no longer registers, and the detection-loss rows come out wrong on contrast B. None of these destroys data; R7 is the only path to losing (re-derivable, hours-long) live aggregates.

## What flips the verdict

Fix R1 (regenerate the G3 reference from the base commit's `hiding_drivers.py`, re-budget C3), R2 (rewrite A5/P0 against Revisions 2–3, add the S4 bound and C-sign classification), R3 (manifest-driven population resolution with status), R4 (either list the shard-limit change or drop smoke mode), and R7 (assert the output root). R5 is a registration decision for `experiment-designer` that must land before C10, not before implementation; R6 is already closed by Revision 3.
