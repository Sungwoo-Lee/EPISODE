## Verdict (plain-language entry point)

The May replication trains each agent through five stages that alternate between a world where the predator hunts ("active") and one where it never does ("passive"). This driver asks the pre-registered question A4: when the world switches, do the two agent types (ordinary and modulated) change their internal processing *together* or *independently*? It measures how much each agent's layer moved between consecutive stage ends (one minus how well the earlier snapshot linearly predicts the later one, on both worlds' probe episodes — eight numbers per agent), subtracts how much the agent drifts within a single stage anyway, checks that both agent types moved more than they drift, and then asks whether the eight-number movement profiles of a modulated and an ordinary agent correlate as well as two ordinary agents' profiles do. It also re-reads the layer-similarity verdict (A1) at every stage end on that stage's own world. All of that goes into the evaluator that was signed off earlier; the driver forms no verdict itself.

**It is safe to run.** I found no Critical finding. The row alignment is by probe row index and is checked by a stored hash on every activation file; column admission is decided on the outer training fold only; the two "one minus predictivity" signs are right; folds do not leak; the reused primary-cell result is pinned to the same rules sha; every threshold and list comes from the rules file's `parameters:` block; and I verified on the real probe files (not the test fixture) that the two worlds hold the identical 5,000 episode-seed groups, split identically on all five repeats, and draw bit-identical bootstrap resamples — so the driver's "joint draws" assertion will hold on the study data.

**Two Moderate findings**, neither of which changes a number: the end-to-end test does not pin the sign of the *bootstrap* path the verdict actually reads (a sign flip in that one line would pass all 13 tests, because the correlation statistic is blind to it and the test accepts any reading word); and the driver reuses an A1 result that was generated on a dirty working tree without recording that provenance in its own output. Both are one-line fixes to apply before the output is cited.

**Rulings on the developer's two readings** (details in "The two readings" below): (1) taking G1/G3 for a stage-end cell from the store-generating captures on the same probe is the letter of the rule applied where the rule is defined, not an extension — sound; (2) resampling the same episode-seed groups on both worlds per draw is stronger than the rules require and coherent with what the rules say the bootstrap covers — sound, and verified on disk.

## The two readings

### 1. G1 / G3 at stage-end cells without their own stores — **sound**

The rules define G1 as "each agent replayed on its own store: argmax action at row t equals the stored action at row t+1 …" and G3 as the row-alignment check on the same replay. Both are properties of a (checkpoint, store-it-generated) pair: they establish that the replay machinery reproduces the recorded trajectory and that the row layout is read without an off-by-one. Those pairs exist for every agent on each probe — `final` on the active probe and `stage_end:3` on the passive probe — and the rules apply gates study-wide ("a failed gate blocks every verdict word"), not per cell. Taking G1/G3 from the store-generating captures on the same probe is therefore the rule evaluated where the rule is defined. What is *not* covered by G1/G3 for a non-generating checkpoint — that this particular checkpoint's forward pass was reconstructed correctly — is exactly what G2 checks per capture, and the driver includes the cell's own captures in G2 (`cell_gates` passes `reps + gen`). The output states the reading (`gates_reading`). One recommendation, not a blocker: the rules' own `revision_policy` names "undefined case" as the trigger for a rules entry, so the designer should add a one-clause `applies_to` note to `gates.G1_self_replay` / `G3_alignment` at the next revision rather than leaving the reading only in tooling prose.

### 2. "Bootstrapped jointly" as the same groups on both worlds — **sound, and verified on disk**

The rules' `common.bootstrap.joint` says "one resample of groups per draw, applied to every agent and every pair at once … so pair-to-pair comparisons are paired." For the co-movement comparison (OO pairs against MO pairs) that only requires that draw k mean the same thing for every *agent*, which holds within a probe by construction. The driver goes further: because both probes are pooled from stores that share `seed_base`, both hold the same 5,000 `episode_seed` groups, and with the same split seed and the same bootstrap seed the group split and the resample positions are identical on both probes, so draw k on the active world and draw k on the passive world are the same reset draws. This is coherent with `what_it_covers` ("which episodes happened to be sampled into the probe") — the same episodes on both worlds — and is the more conservative construction (one source of sampling variation across the whole 8-entry profile rather than two). Verified on the real probe files: `active` 148,602 rows / `passive` 148,770 rows, both exactly the same 5,000 distinct groups (0 only-active, 0 only-passive); `test_groups` equal on 5/5 repeats (1,000 held-out groups each, above the G6 floor of 500); bootstrap position arrays bit-identical on 5/5 repeats. The driver's assertion (line 248-251) will pass; L3 suggests also asserting the positions directly.
