Water at Level 06

A design page for the next body system. Before any code is written, it works out how the planned water settings — how fast thirst drains, how much one step in the pond gives back, how big the grid is and where the pond may sit — change how hard the world is, and shows how the episode dashboard will draw the pond and the new hydration level.

01 What this page is for

The agent will get a new internal state, hydration, and a new resource, a pond. Unlike food, the pond never runs out and stays put for the whole episode, so the agent can always drink there — as in EVAAA, the reference 3-D environment this follows. That turns drinking into a navigation task: remember where the water is and go back.

One difference from EVAAA matters. EVAAA's agent sees and smells from its own point of view in 3-D, so its senses never say which way is north. In our grid they do: the vision and smell grids are laid out north-up. A pond that sat in the same place every episode could be found by a fixed route, with no memory at all. So the pond's place changes between episodes, drawn from a list of candidate spots in the config (or anywhere, or always the centre).

The plan for all of this is written and reviewed but not approved for building (docs/develop/active/thirst/THIRST_WATER_PLAN.md). The user asked for this page first: calculations and a simulation of how the settings shape the difficulty, and the updated rendering.

The answer, in one paragraph

At the planned settings — thirst kills 160 steps after the comfortable middle, a step in the pond gives back a net 5, a 10×10 grid with the pond at one of four corner spots — the rules themselves are gentle. A scripted agent that knows where the pond is lasts the full 500 steps in 95 % of episodes, against 98 % with water switched off; one that must first find the pond lasts in 93 %. The price of water at 10×10 is not in the clock but in time spent exposed: about 2.4 pond visits per episode of about 22 steps each, all outside cover, which at the hit rate measured on real level-05 agents carries about 44 points of injury per episode (Figure 9). Two dials make water a real problem. A larger grid does it fast: at 20×20 an agent that must find the pond survives in only 41 % of episodes. A larger gain per step shortens the exposed stay (22 steps per visit at the planned 5.625, 10 at 12.6) but makes accidental over-drinking more likely. Centre placement is the easiest and should not be used: the pond never moves, so it can be found by route, not by memory.

One correction to the plan

The plan (Revision 1) says that with starting hydration drawn from the full 0–200 range, about 5 % of episodes die of thirst by step 16 "whatever the agent does". That counts every episode whose water would run out if it never reached the pond. The pond is a median 6 steps away at 10×10, so most of those episodes can be saved: the simulated agent loses 1.8 % of episodes to thirst, nearly all in the first 10 steps (Figure 8). The plan's number is an upper bound, not a floor.

03 How long each need lets the agent go

Why this first. The user set a target before any number was solved: thirst should be the slowest clock, 150–200 steps from comfort to death, so water is a background need rather than a third race against hunger and cold. This checks the planned rates hit it, next to the clocks the agent already lives with.

04 The two water dials

Why. Two numbers set everything the body does with water: the drain, which sets how long the agent can stay away, and the gain, which sets how long it must stand in the pond to refill and how quickly standing there turns lethal. Each was placed against a stated target.

05 Where the pond can be, and how far it is

Why. The placement mode decides two things at once: how far the agent walks to water, and how much it must work out each episode to know where the water is. The second is the point of moving the pond.

Centre placement defeats the reason the pond moves: a pond that is always in the middle can be reached by a fixed route learned once, which is exactly what north-up senses would allow. It stays in the plan as a mode, but it should not be a training world.

Simulation: the planned rules with a scripted agent

06 What the simulation is, and is not

Water does not exist in the environment yet, so difficulty is measured on a reduced copy of level 06 run by a scripted agent — a fixed rule, not a trained policy. It is the same approach as the internal-state study, and reuses its pieces.

  • Food and temperature use that study's copy of the environment's body update, checked against the real environment over 4,000 steps (largest difference 0.00002). Water uses the plan's rule, since there is no code to check it against.
  • The map has 1–3 fires, 1–4 food items (12 bites each, then the item moves), one 2×2 pond, and cell temperatures set by distance to the nearest fire as measured on 300 real level-05 resets.
  • The agent camps on the fire ring, because cold is the fastest clock. When a need's spare time — steps until it kills, minus the walk to its nearest source — falls below 25 steps, it goes and refills that need (water to 160, food to 160, body temperature to +4.5°).
  • Two versions: one that knows where the pond is from step 1, and one that must find it. The second knows the placement mode but not the spot drawn, and discovers the pond when a pond cell comes within 2 cells (the vision range). Under the list mode it checks the nearest unchecked candidate; under random it walks to the nearest cell it has not yet seen.
  • Not modelled: predators, injury and smell. So survival here is an upper bound: a trained agent will do worse. Section 12 puts back the cost the missing predators would add.

Each setting is 2,000 episodes. The reference for every figure is the same world with water switched off, where the agent lasts 500 steps in 97.9 % of episodes at 10×10 (the rest starve, mostly from a near-empty start).

07 The drain rate

Why. Figure 2 fixed the drain by arithmetic. This asks what it costs an agent that must also eat and stay warm.

08 Grid size and placement mode

Why. Figure 3 showed walks double with grid size, and that the modes differ in how much there is to search. This asks what that does to survival once food and fire must be served too.

09 The difficulty map

Why. Drain and grid size were varied one at a time above. Together they show where the planned world sits and how far it is from a hard one.

10 The water consumption value

Why. The gain per step decides how long each visit lasts — and the pond is the one place the agent must return to, in the open, where predators can come. That makes the gain the dial for how much a drink risks.

11 What the full starting range costs

Why. The user chose to draw starting hydration from the whole 0–200 range, so that training covers every internal state the experiment environment will later set by hand. Some episodes will then start close to death. This measures how many are lost.

12 The cost the simulation leaves out

Why. The simulation has no predators, and on real level-05 runs injury, not hunger or cold, is what kills. The pond is not cover, so every water step is exposed. This puts a price on those steps.

14 The settings, as options

The planned settings make a world where water is a real but gentle need. If the goal is a world where the agent's best move depends on thirst together with hunger, cold and danger — the state-dependence the modulator is meant to exploit — the page suggests these levers, strongest first.
