Code-Graph Benchmark

Do code-graph tools make Claude Code better at changing this repo? We replayed six real past changes, 54 times in total, and measured.

PURPOSE

Graft and Graphify build a map of a codebase (which function calls which, what each file does) and hand it to a coding agent, so that the agent spends less time searching. Their authors report fewer tokens and more solved tasks. This page tests that claim on this project's own code.

Six real multi-file commits from this repo's history were turned back into tasks. Each was attempted three times by three groups of Claude Code sessions (model: Sonnet): plain, with Graft, and with Graphify. Every attempt was graded by the original commit's own tests.

Findings

  • No benefit detected for either tool. All three groups solved every task: 18, 18 and 18 of 18, with 0 broken existing tests.
  • No cost difference. Task by task, time, tokens, tool calls and turns were within a few percent of plain Claude Code, and every 95% interval includes no change (figure 2).
  • The agents did not use the tools. Graft's tools were connected in 18 of 18 runs and its repo map was injected in 18; the agent called a Graft tool in 0. Graphify agents skimmed its report in 12 of 18 runs and ran a Graphify command in 0.
  • Not adopted. The one favourable number (Graft 36% faster by pooled median) does not survive a task-by-task comparison; see section 03.

01 What was tested

Each task is a real commit. The agent got the repo as it was just before that commit, and an issue-style description of the change that names what the tests check (config keys, mode names) but never names the files to edit.

How it was kept fair

  • Graded by tests. An attempt counts as correct only if every test the real commit made pass now passes, and every test nearby that passed before and after the real commit still passes (between 21 and 672 tests per task).
  • No answers in the repo. The docs/ folder, which holds the plans written before each change, was removed from every copy, and a script checked that no file outside the edited ones mentions a name the task introduces.
  • Each tool set up as its authors intend. Graft with its hooks, its six MCP tools and full Sonnet-written summaries; Graphify with its project CLAUDE.md rule, its hook and its skill.
  • Sandboxed. Every agent ran with the real repo invisible and only its own copy writable.

03 Why no benefit here

There was nothing left to improve. Plain Claude Code solved every task every time. Two explanations fit, and this test cannot separate them. Either Claude finds the right files easily in this consistently named, heavily commented repo, or the task descriptions pointed close to the code because they had to name everything the tests check. The published gains for these tools come from harder benchmarks where the plain agent often fails.

The agents ignored the tools. Even with Graft's map injected into every session, and a Graphify rule in CLAUDE.md saying to read its report before any search, the agents went straight to grep and reading files. Graft agents even excluded the graft/ folder from their searches.

Fixed context dominates the token count. Every attempt re-reads about 60,000 tokens of system prompt and project instructions on each turn. A saving of a few thousand tokens in searching would not show.

The one favourable number, and why it is not a result

Pooling all 18 attempts, Graft's median time is 36% lower than plain Claude Code's (5.1 min against 8.0 min), which meets the pre-registered 25% bar as literally written. The rule did not say which average to use. By pooled mean the gap is 21%, and task by task it is 1%: Graft was faster on 3 of 6 tasks and slower on the rest. We chose the task-by-task comparison after seeing the data. That choice is disclosed here, and the rule is recorded as not decisively met.

04 Limits and corrections

  • Small sample. 6 tasks × 3 attempts per group. A moderate speed-up cannot be ruled out, and a correctness gain could not appear at all, since every group scored 18/18.
  • Run order. Runs were not fully interleaved. The first round of plain and Graphify attempts ran before the Graft graphs were built, and machine load varied through the day.
  • Grader gaps, no effect observed. Existing test files an agent edited were not reset before grading; every such edit was checked and was additive or stricter. File recall is capped below 1 on T7 and T8 because the real commit also added config files no test needs.
  • A first test was wrong, and this one replaces it. On 2026-09-22 Graft was judged unhelpful from five lookup questions, run with its hooks and tools inactive and with every question answerable by one grep. That test could not have shown the benefit these tools claim.
  • Two task descriptions were corrected mid-run. T6 told agents to delete unreachable code, and they deleted a function the tests still call; T8 did not pin the order the tests require. Both were fixed, and the 4 attempts made with the old wording were discarded and repeated.
  • A review corrected the write-up. An independent review of the verdict found that it claimed the tools had no effect (the data only show none was detected), argued that an unused tool cannot act (Graft still injects context), and misdescribed why Graphify's nudge did not change behaviour. All three are fixed on this page.

05 What to do

  • Do not adopt Graft here. It costs a model-written summary build (about 42 minutes for the first snapshot) and a short delay on every message, for no measured gain.
  • Graphify costs almost nothing to rebuild (about 9 seconds), but agents barely use it. Either keep it current for people who want an overview, or drop the two agent profiles that tell agents to read its report.
  • A re-test is only worth it on harder tasks, where plain Claude Code sometimes fails and the description does not point near the code. That is the only setting in which these tools could still show a correctness gain.

06 Terms

fail-to-pass
A test the real commit added or fixed: failing before the change, passing after. An attempt must make all of them pass.
pass-to-pass
A nearby test that passed both before and after the real commit. An attempt must not break any.
task-paired ratio
Tool group's median on a task divided by plain Claude Code's median on the same task, averaged over tasks on a log scale.
MCP tools
Functions a tool exposes to Claude Code (for Graft: find code, trace callers, list a file's API).
hook
A script Claude Code runs automatically at set moments, such as session start or each prompt; Graft uses these to inject its map.
