Episode Dashboard Redesign

A plan to rebuild the frame drawn for every step of an evaluation video, so that no panel or label can ever land on top of another, frames render faster, and the same drawing can be scrubbed step by step in a viewer — built beside today's video pipeline, which stays exactly as it is.

PURPOSE

Every evaluation episode this project records can be turned into a video. Each frame is a dashboard: the agent's internal readings on the left (satiation, interoceptive nociception, body temperature), a close-up of the grid around the agent in the middle, and its outside-world senses on the right (olfaction, extero nociception, thermoception, collision, vision). These videos are how people check what an agent actually did.

The frames drawn today have text printed on top of other text, most visibly since the temperature system added two panels. An April redesign was half built and never used, and it has its own collisions. The cause is structural: the drawing library's automatic layout cannot see text placed inside a panel, so moving numbers around only moves the collisions.

This page shows the problem in real frames, the proposed system, a sketch of the new dashboard drawn from a real recorded episode, the choice of drawing toolkit, and the decisions that are yours to make. The plan itself is docs/develop/active/refactors/RENDERER_LAYOUT_REDESIGN.md.

Your constraint: today's video pipeline is preserved

Nothing that training or evaluation runs today is edited while the new renderer is developed. The production renderer, the script that turns recordings into videos, the in-training render dispatch, the evaluation loop, the recorder and the sense adapter are all frozen. The new renderer gets its own script and writes to its own videos_v2/ folder, so it cannot overwrite a production video. A guard records the frozen files' contents and fingerprints of production frames before work starts, and must pass after every phase. Moving any training or evaluation video to the new renderer is a later decision of yours, with no setting or default changed before then.

01 What goes wrong today

Both frames below show the same moment: the campfire temperature world, after five fixed actions from the same starting world. The left frame is the renderer every video uses today (renderer.py, called V1 here). The right is the April attempt (renderer_v2.py), which nothing calls. They are the renderers' own output, saved as PNG by their script rather than redrawn in the house figure style, because the renderers' look is the subject.

Why tuning cannot fix it

The drawing library, Matplotlib, has an automatic layout that "only considers ticklabels, axis labels, titles, and legends", so other text "may be clipped and also may overlap" (its own constrained-layout guide). V1 avoids the automatic layout by placing every label at hand-typed coordinates, which are only right for the set of senses they were typed for — the temperature work already had to add a special case. A guarantee needs three things neither renderer has: a step that sizes each panel from what it contains, drawing that cannot leave its box, and a test that checks the finished pixels.

02 The proposed system

The new renderer is built alongside V1, which stays the default for every video. It works in five steps, of which the first three happen once per episode rather than once per frame.

STEP 1
Read the recording The same files the video path reads today: one .rec.gz per episode plus the run's saved environment settings. Read-only, no new file format, and recordings made before the temperature system keep working.
STEP 2
Ask each sense what it needs A registry holds one entry per sense: whether it is present in this world, the smallest box it can be drawn in, and which numbers it shows. Every sense in the observation must have an entry, or the renderer refuses to start and names the missing one — so a sense can never be silently dropped, the way proprioception is today. A value appears as "observed" only if the agent observes it. Adding a future sense means adding an entry, never touching layout code.
STEP 3
Give every panel its own box A small packer stacks the present panels in three columns and hands the spare height to the minimap and the grid view. Boxes cannot overlap by construction. If the panels do not fit, it stops with an error listing what asked for how much space, before a single frame is drawn — a colliding frame is never produced. All text is measured and shrunk to fit its box down to a floor; a number is never cut off.
STEP 4
Build the figure once, update it per step Today every step rebuilds the whole figure. The new renderer creates every bar, label and icon slot once per episode and only changes their values per step. Its speed target is half V1's time per frame, measured on the same lab node.
STEP 5
Two outputs from one drawing MP4 videos written by the new renderer's own script into videos_v2/, and a local step-scrubbing viewer that asks the same renderer for each frame and lists the exact numbers that frame shows. The viewer cannot disagree with the video, because it is the video's own drawing code.

Carried over from the April plan (your 2026-09-14 answers)

  • One vitals card holding every observed internal reading as a row, freeing space for a larger minimap.
  • True value beside the observed value when perceptual noise is on, with a tick on the bar; no difference (Δ) text anywhere.
  • The last action as a badge in the grid view's title strip instead of its own panel.
  • Horizontal legends above bars, replacing tiny rotated labels.

04 Senses that read further

Olfaction and vision no longer read only the agent's own cell. Since the directional-sensors change, each can read a diamond of cells around the agent, and the range has no upper limit: a diamond of range r holds 2r²+2r+1 cells. The worlds trained on today use olfaction range 1 (5 cells × 5 smell channels) and vision range 2 (13 cells × 8 channels, 104 numbers). In a 306-pixel side panel that leaves 61 pixels per cell at range 2 and 34 at range 4 — not enough for a bar per channel. The three figures below draw the same real world state three ways, at the configured ranges and at two stress ranges, so you can choose.

Already decided (your answers, 2026-09-14)

  • Placement: when a sense no longer fits the side column, the layout switches — once per world configuration — to a wide sensor band under the grid view. The frame size stays the same, and the fit-or-fail check still guards it.
  • Support: the ranges in use today are tested, plus stress tests at ranges 3 and 4; the largest range that fits is written down, and anything larger stops with an error naming the sense.
  • Still open: which of the three drawings below the new renderer uses.

05 Choosing the drawing toolkit

The registry, packer and checks are the same whichever toolkit draws the panels. What differs is speed, how much existing drawing code carries over, and what runs where videos are rendered. Speeds marked "est." are estimates from the research note; the plan's first phase measures toolkit A before any panel is written.

Why A is recommended. It fixes every defect class through the registry, packer and pixel check, none of which depend on the toolkit; it removes the largest cost (rebuilding the figure every step) without installing anything; and its viewer shares the video's drawing code. If the first phase measures A slower than half of V1, the plan comes back to you with B. What C would add is a static, shareable viewer with instant scrubbing and hover inspection of a cell. If that is worth a browser in every render worker, C is the right pick, and only the drawing and viewer parts of the plan change.

06 How we will know it works

CHECK
Today's pipeline did not move The frozen files' recorded contents and fingerprints of production frames for four worlds are re-checked after every phase. Any difference stops the work.
CHECK
Real recordings, across worlds Recordings made through the production recorder for the default world, interoceptive nociception with and without noise, the campfire world, directional olfaction and a location sensor, plus real recordings from trained agents, including one made before the temperature system existed.
CHECK
Collisions found from pixels, not from the layout Each label is rendered alone and with everything else, and the check flags any label whose ink touches another element's ink, a card border, or is cut off. It sorts what it sees itself rather than trusting the renderer's own labels. It must first find the collisions in Figures 1 and 2, and the missing panels in Figure 2; if it reports none, the check is broken.
CHECK
Faster than V1, on the same frames Timed in the same kind of worker process that renders videos in production, on the same lab node, with memory checked to stay flat over ten episodes.
CHECK
Somebody looks A contact sheet of every checked frame and screenshots of the viewer are opened and read. A green automated check is necessary, not sufficient.

07 Decided and open

Decided (your answers, 2026-09-14)

  1. Build it as V2, keep V1. V1 stays the default for every video.
  2. Today's pipeline is frozen during development; switching any video to V2 is a later decision.
  3. Two outputs. MP4 videos and an interactive step viewer over the same recordings.
  4. All four April ideas stand. One vitals card, true value beside observed, action badge, horizontal legends.
  5. Senses that read further move to a wide band under the grid view when they outgrow the side column.
  6. Range support: the ranges in use today plus stress tests at 3 and 4, with the largest range that fits written down.
  7. Drawing senses that read further: option A, a small map per channel (Figure 5).
  8. Internal states: every state is shown twice — what the agent observes, and its true (hidden) value — including states the agent does not observe.
  9. Grid view: no numbers in cells, and a temperature colour scale fixed per world configuration.
  10. Campfire: a new image file, used only by the new renderer.

Open — yours to decide

  1. Toolkit: A with B as fallback, or C.
  2. Name: src/environment/dashboard/ (proposed), episode_dashboard/ or telemetry_view/. It cannot reuse renderer_v2, which another session is still editing; the new entry script and output folder keep the _v2 names (render_recordings_v2.py, videos_v2/).
  3. Frame size: 1440 × 896 pixels (today's videos are 1408 × 1008 after encoding).
  4. Action badge: in the grid view's title strip (as sketched), or over the top-right grid cell.
  5. Proprioception: a panel (as sketched), or "recorded, not displayed". This answer now blocks testing: every world that reads further also observes proprioception, so the renderer refuses to draw them until it is decided.
  6. Minimap: in the left column under the vitals (as sketched), or under the grid view.
  7. Viewer: local only, or also a single-file export for sharing an episode.
  8. Later switch-over: its own reviewed plan when you decide; at that point delete the stale renderer copy in grid_world.py and the unused renderer_v2.py (the latter once the other session's edits have landed and it has been told).
  9. Speed gate: half V1's frame time on the campfire world, and not slower on any other world?
  10. Hiding-predator label: HPR (as sketched), HID or HPD?
  11. Maps from range 1: Figure 5 draws olfaction at range 1 as maps too. Confirm option A applies from range 1, rather than keeping per-cell bars at range 1.
  12. A cell outside the temperature scale: stop the render with an error naming the cell (proposed, matching the project's no-fallback rule), or clamp its colour and outline it.
  13. Temperature scale anchors: keep the design rule (warm at 4× and fire at 10× the upper body limit), or take those two anchors from the world configuration.
