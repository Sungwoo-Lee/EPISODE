Episode Dashboard Redesign

Rebuilding the frame drawn for every step of an evaluation video, so that no panel or label can ever land on top of another, frames render faster, and the same drawing can be scrubbed step by step — built beside today's video pipeline, which stays exactly as it is. The renderer now exists: every dashboard on this page is its output on a real recorded episode.

PURPOSE

Every evaluation episode this project records can be turned into a video. Each frame is a dashboard: the agent's internal readings on the left (satiation, interoceptive nociception, body temperature), a view of the grid world in the middle, and its outside-world senses on the right (olfaction, extero nociception, thermoception, collision, vision). These videos are how people check what an agent actually did.

The frames drawn today have text printed on top of other text, most visibly since the temperature system added two panels. An April redesign was half built and never used, and it has its own collisions. The cause is structural: the drawing library's automatic layout cannot see text placed inside a panel, so moving numbers around only moves the collisions.

This page shows the problem in real frames (section 01), the system that replaces it (02), the new renderer's own output on a recorded episode (03), the encodings for senses that read beyond the agent's own square (04), the choice of drawing toolkit (05), what has been measured so far (06) and the decisions taken (07). The plan itself is docs/develop/active/refactors/RENDERER_LAYOUT_REDESIGN.md.

Your constraint: today's video pipeline is preserved

Nothing that training or evaluation runs today is edited while the new renderer is developed. The production renderer, the script that turns recordings into videos, the in-training render dispatch, the evaluation loop, the recorder and the sense adapter are all frozen. The new renderer gets its own script and writes to its own videos_v2/ folder, so it cannot overwrite a production video. A guard records the frozen files' contents and fingerprints of production frames, and it has been re-run after every phase — 10 files out of 10 unchanged, production frames identical, every time. Moving any training or evaluation video to the new renderer is a later decision of yours, with no setting or default changed before then.

01 What goes wrong today

Both frames below show the same moment: the campfire temperature world, after five fixed actions from the same starting world. The left frame is the renderer every video uses today (renderer.py, called V1 here). The right is the April attempt (renderer_v2.py), which nothing calls. They are the renderers' own output, saved as PNG by their script rather than redrawn in the house figure style, because the renderers' look is the subject.

Why tuning cannot fix it

The drawing library, Matplotlib, has an automatic layout that "only considers ticklabels, axis labels, titles, and legends", so other text "may be clipped and also may overlap" (its own constrained-layout guide). V1 avoids the automatic layout by placing every label at hand-typed coordinates, which are only right for the set of senses they were typed for — the temperature work already had to add a special case. A guarantee needs three things neither renderer has: a step that sizes each panel from what it contains, drawing that cannot leave its box, and a test that checks the finished pixels.

02 The system that replaces it

The new renderer lives at src/environment/dashboard/ and is built alongside V1, which stays the default for every video. It works in five steps, of which the first three happen once per episode rather than once per frame.

STEP 1
Read the recording The same files the video path reads today: one .rec.gz per episode plus the run's saved environment settings. Read-only, and no new file format.
STEP 2
Ask each sense what it needs A registry holds one entry per sense: whether it is present in this world, the smallest box it can be drawn in, and which numbers it shows. Every sense in the observation must have an entry, or the renderer refuses to start and names the missing one — so a sense can never be silently dropped, the way proprioception is today. A value appears as "sensed" only if the agent senses it. Adding a future sense means adding an entry, never touching layout code.
STEP 3
Give every panel its own box A small packer stacks the present panels in three columns and hands the spare height to the World map and the thermoception card. Boxes cannot overlap by construction. If the panels do not fit, it stops with an error listing what asked for how much space, before a single frame is drawn — a colliding frame is never produced. All text is measured and shrunk to fit its box down to a floor; a number is never cut off.
STEP 4
Build the figure once, update it per step Today every step rebuilds the whole figure. The new renderer creates every bar, label and token once per episode and only changes their values per step. Measured against V1 on the same recording, a frame takes 57% of V1's time — your artwork and the two sensory-band panels made it slower, and drawing a window of 25 squares instead of the whole world's 100 more than paid that back.
STEP 5
Two outputs from one drawing MP4 videos written by the new renderer's own script into videos_v2/ — built and working — and a step-scrubbing viewer that asks the same renderer for each frame and lists the exact numbers that frame shows. The viewer cannot disagree with the video, because it is the video's own drawing code; the scrubber in section 03 is that arrangement, exported to a page.

Carried over from the April plan (your 2026-09-14 answers)

  • One Interoception card holding every internal reading as a row, freeing space for a larger World map.
  • True value beside the sensed value when perceptual noise is on, with a tick on the bar; no difference (Δ) text anywhere.
  • The last action as a badge in the grid view's title strip instead of its own panel.
  • Horizontal legends above bars, replacing tiny rotated labels.

04 Senses that read further

Olfaction and vision no longer read only the agent's own cell. Since the directional-sensors change, each can read a diamond of cells around the agent, and the range has no upper limit: a diamond of range r holds 2r²+2r+1 cells. The world in Figure 3 reads both at range 0 — the agent's own square only — so its two sense panels, in the band under the grid view, are named rows with a number each: there is nowhere for that world's smell to be, other than where the agent stands. Other worlds train at olfaction range 1 (5 cells × 5 smell channels) and vision range 2 (13 cells × 8 channels, 104 numbers). In a 306-pixel side panel that leaves 61 pixels per cell at range 2 and 34 at range 4 — not enough for a bar per channel, which is why these senses move into the full-width band. The three figures below draw the same real world state three ways, at the configured ranges and at two stress ranges. You chose option A — and option A is now built: the renderer had no code for a channel map until 2026-09-17, which is exactly why the one recorded world that smells past its own square used to report its smell panel as missing. Figure 9 is that world's frame, drawn by the shipped renderer.

Already decided (your answers, 2026-09-14)

  • Placement: when a sense no longer fits the side column, the layout switches — once per world configuration — to a wide sensor band under the grid view. The frame size stays the same, and the fit-or-fail check still guards it.
  • Support: the ranges in use today are tested, plus stress tests at ranges 3 and 4; the largest range that fits is written down, and anything larger stops with an error naming the sense.
  • Chosen: option A, a small map per channel (Figure 5), from range 1. Figures 6 and 7 stay on the page as the options not taken.

05 Choosing the drawing toolkit

The registry, packer and checks are the same whichever toolkit draws the panels. What differs is speed, how much existing drawing code carries over, and what runs where videos are rendered. Chosen: A, and it met its target. It fixes every defect class through the registry, packer and pixel check, none of which depend on the toolkit; it removes the largest cost (rebuilding the figure every step) without installing anything; and its viewer shares the video's drawing code. The fallback to Pillow was never needed: measured on the same recording, a median frame costs 177 ms against V1's 308 ms — a ratio of 0.57, against a target of at most 0.5 that the plan accepted as met in substance. That number moved twice on 2026-09-17, and both moves are recorded rather than absorbed: drawing your own artwork and the two sensory-band panels made a frame slower, and then restoring the window made it faster again, because the grid view draws 25 squares where it used to draw 100. V1's figure is its own measurement on the same recording and machine; V1 is a frozen file and the guard re-checks that it has not changed. The requirement that matters for training-time rendering — never slower than V1 — holds with room to spare. C was not chosen: its static shareable viewer with hover inspection was not worth a browser in every render worker.

06 What has been checked, and what it found

The checks below were specified before the renderer was written, so that passing them would mean something. Five of them have now run.

PASSED
Today's pipeline did not move The ten frozen files' recorded contents and fingerprints of production frames for three worlds are re-checked after every phase: 10 of 10 unchanged, frames identical, every time.
PASSED
The instrument finds the known defects first The pixel check must rediscover the collisions in Figures 1 and 2, and Figure 2's missing panels, before it is trusted to report none: 7 of 7 fired, at the same rules, elements and pixel coordinates when re-run independently. It was then mutated to see whether it could tell a real instrument from one that flags everything — an always-sounding alarm fails 10 of its tests.
PASSED
Real recordings, across worlds Nine recorded worlds, two frames each — 18 frames, zero findings from the grid-panel rules, with every occupant of every shared square measuring a full 1.000 of its own ink. That matrix was measured before the approved design was restored; since the restoration the same rule has been re-run on a real windowed frame, again with zero findings, and it now covers terrain too — the case the redesign started from, which the older rule exempted by construction. The World map's own rule was retired together with the encoding it measured, rather than relaxed.
PASSED
The overlap defect is fixed, measured two independent ways The automated instrument reproduced an earlier hand measurement exactly, on the design it was made against — floor ink (the share of a square still showing the earlier design's full-square terrain floor) 53.44% and 51.68% against 53.4% and 51.7% by hand, occupant survival 100% against 100%. Terrain is no longer drawn as a floor under its square, so that measurement went with the design it measured; what carries over is the half that matters, occupant survival, still measured at a full 1.000 and now covering terrain as well. The two measurements are independent because the instrument derives which occupants a square holds from the recorded snapshot, while the renderer derives it from its own code, and the two agree on every square.
PASSED

Both of 2026-09-17's changes are in that number: your artwork and the two sensory-band panels cost about 20% more per frame, and the restored window won more than that back by drawing 25 squares instead of 100. Not yet the final speed gate, which needs a lab node, a pool worker and at least 200 frames.

It writes real videos

The new renderer's own entry point turns a folder of recorded episodes into MP4s. The first full one is a 75-step campfire episode at 1440 × 896, 15.0 seconds at 5 frames a second. Its frame count is not taken on trust from the writer: the finished file is re-opened and decoded, and 75 decoded frames against 75 recorded steps is what the check compares. Rendering the same folder twice produces byte-identical files, so the video can be compared against a later one. It writes only into videos_v2/, is called by nothing automatically, and has no code path that deletes a file.

07 Decisions

Decided — scope and pipeline (2026-09-14)

  1. Build it beside V1, keep V1. V1 stays the default for every video.
  2. Today's pipeline is frozen during development. Switching any video to the new renderer gets its own reviewed plan later; deleting the unused grid_world.py renderer copy and renderer_v2.py is not approved.
  3. Toolkit: Matplotlib with our own layout, figure built once per episode; Pillow as the fallback if the first phase missed the speed target. It did not, so the fallback was not used.
  4. Speed target: median frame time at most half of V1's on the campfire world, and never slower than V1 on any other world. Measured at 0.58 of V1 and accepted as met in substance; 0.57 of V1 now that the approved design and its window are both restored, which still meets the "never slower than V1" half.
  5. Outputs: MP4 videos plus a step viewer served from the same drawing code; no static HTML export.
  6. Package name: src/environment/dashboard/, with render_recordings_v2.py writing to videos_v2/.

Decided — what the frame shows (2026-09-14 to 09-17)

  1. Layout and look: Figure 3 is the direction. Frame size 1440 × 896; World map under Interoception; last action as a title-row badge plus a chevron on the agent.
  2. The grid view shows a window of the world — visualization.local_view_size squares centred on the agent, 5 × 5 in every maintained world — inside an arena box of fixed size, so the square size follows the window: 96 pixels at 5 wide, 48 at 10 wide. This restores the approved design and supersedes a whole-world grid at a 50-pixel square.
  3. Terrain is an occupant like any other, drawn as a centred glyph at its own size rather than as the square's floor. A shared square gives each occupant its own slot, up to four, in a fixed draw order.
  4. The World map draws one mark per occupied square over the whole world, in that square's occupant's own icon colour, plus a viewport rectangle showing where the grid view is looking. The wedge encoding it carried while the grid drew the whole world is retired with it — so a square holding two occupants now shows only the last one drawn, and two occupants of the same shape cannot be told apart on the map.
  5. Internal states: every state shown twice, sensed and true, including states the agent does not sense.
  6. Senses that read further: option A, a small map per channel, from range 1; placed in a band under the grid view when they outgrow the side column.
  7. Temperature colours: one range per episode, shared by all its steps; the setpoint near-white and the survivable body band pale, colour deepening only beyond it. No numbers in grid squares.
